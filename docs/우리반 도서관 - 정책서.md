# 우리반 도서관 - 정책서

Sep 29, 2026 · @바바바

## 문서 목적

이 문서는 우리반 도서관 앱을 운영하는 데 필요한 규정과 원칙을 정의합니다. 특히 보안 수준, 콘텐츠 관리 기준, 개인정보 노출 범위처럼 판단 기준이 필요한 사항을 명확히 해, 개발과 운영 과정에서 일관된 기준으로 의사결정할 수 있도록 합니다.

## 계정 및 코드 관리 정책

- 이 앱은 보안보다 사용 편의성을 우선하는 교실 내 신뢰 기반 도구로 운영합니다. 유아가 직접 다루는 도구임을 고려해 복잡한 인증 절차를 두지 않습니다
- 아이는 개인 계정이나 로그인 없이 학급 코드 하나로 도서관에 입장하며, 입장 후에는 별도 인증 없이 작가실과 서고, 옥상을 자유롭게 오갑니다
- 작가실과 미니 정원에는 PIN 등 별도의 보호 장치를 두지 않습니다. 목록에서 자기 이름을 선택하면 바로 입장하며, 다른 아이의 공간을 실수로 건드리는 상황은 감수하는 대신 사용성을 우선합니다
- 학급 코드는 학기/학년 동안 고정하며 재발급 기능은 1차 범위에 포함하지 않습니다
- 작가 코드는 학부모 전달용으로, 유출되거나 잘못 전달된 경우 선생님이 관리자 모드에서 재발급할 수 있습니다. 재발급 시 기존 코드는 즉시 무효화됩니다

## 콘텐츠 발행 및 사후관리 정책

- 아이가 만든 책은 선생님의 사전 승인 없이 발행 즉시 1층 서고에 공개됩니다
- 발행 후에도 아이는 자유롭게 사진 순서·녹음·페이지를 수정하거나 책 전체를 삭제할 수 있습니다
- 부적절하거나 문제가 있는 콘텐츠는 선생님이 사후에 관리합니다: "숨기기"는 즉시 비공개 처리하며 언제든 복구할 수 있고, "삭제"는 휴지통으로 이동해 30일간 보관 후 복구하지 않으면 자동으로 영구 삭제됩니다
- 독서 기록(녹음/글)도 동일한 기준으로 선생님이 숨기기·삭제할 수 있습니다

## 개인정보 및 실명 노출 정책

- 1층 서고와 학부모 열람 화면에는 작가(아이)의 실명이 표시됩니다. 이는 같은 반 친구·학부모 사이의 소규모 신뢰 기반 공유를 전제로 한 설계입니다
- 학부모 동의 여부를 기록하거나 관리하는 기능은 앱 범위 밖입니다. 실명 노출에 대한 동의를 구하는 절차는 선생님이 앱 밖에서 별도로 안내하는 것을 전제로 합니다
- 사진, 음성 등 아이가 등록한 콘텐츠는 모두 클라우드에 저장되며, 접근은 해당 학급 코드 또는 작가 코드를 가진 사람으로 제한됩니다

## 작가실/미니 정원 비활성화 및 삭제 정책

- 선생님이 작가실을 삭제하면 해당 작가실만 비활성화되어 2층 로비 목록에서 사라지지만, 이미 발행된 책은 1층 서고에 그대로 남습니다. 다만 비활성화된 작가의 작가 코드로는 더 이상 열람할 수 없습니다
- 미니 정원도 동일한 원칙으로 관리하며, 선생님이 정원을 삭제(비활성화)할 수 있습니다
- 작가실·미니 정원 삭제는 콘텐츠 자체를 삭제하지 않고 접근 경로만 차단하는 방식으로, 아이들의 창작물을 최대한 보존하는 것을 원칙으로 합니다

## 독서 육성 시스템 운영 정책

- 독서 등록(먹이 추가) 횟수에는 하루 또는 기간 제한을 두지 않습니다. 등록 대상 책도 우리반 도서관 안의 책으로 제한하지 않고, 집에서 읽은 책 등 무엇이든 자유롭게 등록할 수 있게 합니다. 이는 아이들의 독서 동기를 제약하지 않는 것을 우선한 정책입니다
- 도감에 등장하는 동물은 특정 종류나 개수로 제한하지 않고 다양하게 구성해, 아이들이 지속적으로 새로운 동물을 모으는 재미를 느끼게 합니다
- 성장을 마친 동물은 도감 카드로 영구 보존되며, 화면에는 곧바로 새 알이 생겨 다음 동물을 키우는 사이클이 반복됩니다

## 관리자 권한 범위

선생님은 다음과 같은 운영 기능만 수행하며, 아이가 만든 사진·녹음 콘텐츠 자체를 직접 수정하지는 않습니다.

- 발행된 책 숨기기·삭제·복구
- 독서 기록(녹음/글) 숨기기·삭제
- 작가실/미니 정원의 이름 수정, 삭제(비활성화)
- 작가 코드 확인 및 재발급
- 학급 코드 확인
- 학급 개요(작가실 수, 발행된 책 수 등) 조회

## 향후 정책 검토 필요 사항 (2차 범위)

- 학부모 동의 여부를 앱 내에서 기록·관리하는 절차 도입 여부
- 여러 학급/반을 동시 지원하는 멀티테넌트 구조로 전환할 때의 데이터 격리 정책
- 학급 코드 재발급 기능과 그에 따른 기존 이용자 안내 절차
- 도감에 이벤트성 특별 동물을 추가할 경우의 운영 기준
